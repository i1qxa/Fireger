# Firebase Multi-Project Manager

Веб-приложение на Kotlin для управления несколькими Firebase проектами из одного места. Позволяет управлять правилами безопасности и данными Realtime Database для всех ваших проектов через единый интерфейс.

## Возможности

- ✅ Добавление и управление несколькими Firebase проектами
- ✅ Просмотр и редактирование правил безопасности Realtime Database
- ✅ Просмотр, редактирование и удаление данных в Realtime Database
- ✅ Веб-интерфейс на Kotlin с использованием Ktor HTML DSL
- ✅ REST API для интеграции с другими приложениями

## Требования

- Java 17 или выше
- Gradle 7.0+
- IntelliJ IDEA (рекомендуется)

## Установка и запуск

1. Откройте проект в IntelliJ IDEA:
   - File → Open → выберите папку проекта
   - Дождитесь синхронизации Gradle и загрузки зависимостей

2. Запустите приложение:
   ```bash
   ./gradlew run
   ```
   Или через IntelliJ IDEA: найдите класс `Application.kt` и запустите его

3. Откройте браузер и перейдите по адресу: `http://localhost:8080`

## Использование

### Добавление проекта

1. Перейдите на страницу "Проекты" → "Добавить проект"
2. Заполните форму:
   - **Название проекта**: любое удобное имя для отображения
   - **Сервисный ключ**: загрузите JSON файл сервисного ключа из Firebase Console
   - **Database URL**: опционально, если отличается от стандартного
3. Нажмите "Добавить проект"

### Получение сервисного ключа

1. Откройте [Firebase Console](https://console.firebase.google.com/)
2. Выберите нужный проект
3. Перейдите в Project Settings → Service Accounts
4. Нажмите "Generate new private key"
5. Скачайте JSON файл и используйте его при добавлении проекта

### Управление проектом

После добавления проекта вы можете:

- **Просмотреть детали**: нажмите "Управление" на карточке проекта
- **Редактировать**: изменить название или обновить сервисный ключ
- **Удалить**: удалить проект из системы (файл ключа также будет удален)

### Управление правилами безопасности

1. Откройте страницу проекта
2. Перейдите на вкладку "Правила безопасности"
3. Отредактируйте правила в редакторе
4. Нажмите "Сохранить правила"

**Примечание**: Обновление правил через REST API может требовать дополнительной настройки. В некоторых случаях может потребоваться использовать Firebase Console или Firebase Management API.

### Управление данными

1. Откройте страницу проекта
2. Перейдите на вкладку "Данные"
3. Укажите путь к данным (например, `/users` или `/posts`)
4. Нажмите "Загрузить" для просмотра данных
5. Отредактируйте данные в формате JSON
6. Нажмите "Сохранить данные" или "Удалить данные"

## Структура проекта

```
src/main/kotlin/com/firebasemanager/
├── Application.kt              # Точка входа
├── config/
│   └── AppConfig.kt            # Конфигурация проектов
├── firebase/
│   ├── FirebaseManager.kt     # Управление подключениями
│   └── FirebaseProject.kt     # Модель проекта
├── models/                     # Модели данных
├── routes/                     # REST API маршруты
├── services/                   # Бизнес-логика
└── web/                        # Веб-интерфейс
    ├── WebRoutes.kt
    └── templates/             # HTML шаблоны
```

## Конфигурация

Проекты хранятся в файле `projects.json` в корне проекта. Сервисные ключи сохраняются в `config/service-accounts/`.

**Важно**: Эти файлы добавлены в `.gitignore` и не должны попадать в систему контроля версий!

## REST API

### Проекты

- `GET /api/projects` - список всех проектов
- `GET /api/projects/{id}` - получить проект
- `POST /api/projects` - создать проект (multipart/form-data)
- `PUT /api/projects/{id}` - обновить проект
- `DELETE /api/projects/{id}` - удалить проект
- `POST /api/projects/{id}/test` - проверить подключение

### Правила

- `GET /api/projects/{id}/rules` - получить правила
- `PUT /api/projects/{id}/rules` - обновить правила

### Данные

- `GET /api/projects/{id}/data?path=...` - получить данные
- `PUT /api/projects/{id}/data?path=...` - обновить данные
- `DELETE /api/projects/{id}/data?path=...` - удалить данные

## Безопасность

- Сервисные ключи хранятся локально и не передаются через сеть
- Файлы ключей автоматически исключены из git
- Рекомендуется запускать приложение только в доверенной сети
- Для продакшена добавьте аутентификацию и HTTPS
